**Added:** the doc-vs-code lens (`analysant::doccode`) and `analysant findings|counts <dir> --code <dir>`. A document's code spans that name a Rust item (`pick_route`, `PlanStore`, `Cache::resolve`; the shape rule is the Rust pack's, `RustPack::code_reference`, with its `external-roots` and `path-prefix-words` data files) are looked up in a `CodeIndex` built from the files `git ls-files` lists in the code directory, and five kinds are reported: `absent`, `tests-only`, `uncalled`, `dead-callers`, `shared-name`. Every sentence says that uses are counted by bare name, one hop, with no call graph; every finding carries what was searched and a `KnownPresent` control that is a different claim of the corpus, and a name is withheld (never reported absent) when no such control exists or no Rust item was indexed. Without `--code` the output is byte-identical to before. `analysant` now depends on `analysant-rust`. CI's `reference-gate` job also runs the lens on the reference tree and fails, never skips, when the tree is missing.
