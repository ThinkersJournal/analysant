The ledger file and re-identification across edits (SPEC-STEP1 1.4, 1.9, D3, D7): `analysant::ledger_file` (`.analysant/ledger.jsonl`, one JSON record per unit event: `minted`, `revised`, `moved`, `gone`; event ids are a hash of the event and are checked on every read, so a hand-edited line is refused; old text is never deleted; `merge` is a union on event id, in one canonical order, so either merge order writes the same bytes; two branches that reword one claim differently are reported as a `Conflict` with both rewordings kept) and `analysant::identity` (`reidentify` aligns a fresh extraction of one document to the ledger's last state: exact text keeps the id, a moved section keeps it, an in-place edit keeps it with `revision + 1`, new text mints, an old claim with no match is marked `gone`; a tie the rules do not break is reported as an `identity:ambiguous` finding and nothing is decided). `UnitId::from_raw` is now public and `UnitId::parse` is the inverse of `Display`. New dependencies: `serde` and `serde_json`. The module proposes events and writes nothing; only a writing tool calls `ledger_file::write_file`. Version is PM-allocated.
